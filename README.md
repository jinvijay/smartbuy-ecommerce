# SmartBuy

A simple eCommerce storefront. React + Vite frontend, Express backend, Neon Postgres for
persistence, Better Auth for email/password authentication.

## Architecture

Everything runs as **one Node process**. Express serves the JSON API under `/api/*` and,
in production, also serves the built frontend (`dist/`) as static files with an SPA
fallback. There's no separate frontend server to deploy or keep running — build once,
start one process.

```
src/       React frontend
server/    Express API + Postgres access + Better Auth
dist/      Built frontend (generated by `npm run build`)
```

The cart stays in the browser's `localStorage`. Products, orders, and user accounts are
persisted in Postgres. Checkout requires signing in; orders are tied to the account that
placed them.

## Setup

1. Create a free [Neon](https://neon.tech) project and copy its connection string.
2. `cp .env.example .env` and fill in `DATABASE_URL` and `BETTER_AUTH_SECRET` (generate
   one with `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`).
3. `npm install`
4. `npx @better-auth/cli migrate --config server/auth.js -y` — creates the `user`,
   `session`, `account`, and `verification` tables.
5. `npm run seed` — creates the app's own tables and loads the starter product catalog.

## Development

```
npm run dev
```

Runs Vite (port 5173, with hot reload) and the Express API (port 3001) together. Vite
proxies `/api` (including `/api/auth/*`) requests to Express, so the browser only ever
talks to `localhost:5173`.

## Production / single-artifact deploy

```
npm run build   # builds the frontend into dist/
npm start       # one process: Express serves dist/ + the API on $PORT
```

Deploy this to any Node host (Render, Railway, Fly.io, a single container, a VM) with
just those two commands and the `DATABASE_URL`, `BETTER_AUTH_SECRET`, and
`BETTER_AUTH_URL` env vars set (`BETTER_AUTH_URL` should match the public URL the app is
served at). No separate frontend hosting needed.

## Notes

- Auth is email/password only for now — no email verification or OAuth providers.
- `server/cryptoPolyfill.js` polyfills the global Web Crypto API for Node 18, which
  Better Auth depends on. Harmless on Node 20+, where it's already global.
